# Независимый синтетический контроль v5

Это синтетика одного независимого контекста подготовки. Это **не данные ГПН, не экспертная разметка реальных обращений и не доказательство промышленного качества**. Реализация нового semantic matcher и старые demo_analyze rules до фиксации наборов не читались. Формулировки не подбирались по результатам модели; модельные прогоны при подготовке не проводились.

## Файлы и разделение

| Задача | Tune с разметкой | Контрольные inputs без gold | Отдельный контрольный gold |
|---|---|---|---|
| Группировка и тип | tune.jsonl — 120 | control-inputs.jsonl — 120 | control-gold.jsonl — 120 |
| Подготовка ответа | reply-tune.jsonl — 80 | reply-control-inputs.jsonl — 80 | reply-control-gold.jsonl — 80 |

CONTROL-LOCK.json фиксирует SHA-256 каждого файла, число строк, дату и правила. 24 определённых смысловых семейства tune и 24 других семейства control не пересекаются по целям. Похожие объекты при разных намерениях не считаются одной целью. В каждом наборе группировки также есть 20 недоопределённых/противоречивых обращений и 4 повторных доставки. Это 120 строк, а не 120 независимых реальных пользователей: парафразы, повторы авторов и доставки коррелированы.

Контрольные ответы и словари не включаются в handoff или учебник. До заморозки конфигурации сторона настройки использует только tune. После выбора backend/порогов сохраняются их конфигурация и хэш, затем проводится один конечный контрольный прогон; контрольный gold присоединяется только в оценочном harness. Промежуточная неудача не разрешает менять контроль, переписывать labels или подбирать порог по контрольным результатам. Ошибки разметки требуют отдельной новой версии протокола, а не молчаливого изменения lock.

## Обращения

Inputs: id, product, author_id, source_id, created_at, received_at, channel, text. ID оценки непрозрачный; source_id — идентификатор исходного сообщения. Повторная доставка сохраняет product/source_id/author/text, но получает отдельный id оценочной строки. Один автор может писать несколько раз: голоса считаются внутри темы по различным авторам, а не по числу сообщений.

Tune содержит дополнительный объект gold. Контрольный gold содержит только id и gold, соединение с inputs идёт по id. Определённые topic_id включают product и kind. Виды: wish — новая возможность существующего продукта; bug — явная поломка существовавшего поведения; service — самостоятельная новая услуга/продукт; usability — удобство работающего поведения; unknown — недостаточный или противоречивый контекст. Новизна понятной темы сама по себе не делает её unknown. Для unknown topic_id=null и route=review: неоднозначность не насилуется в одну тему.

Телефонные/ASR/OCR особенности здесь написаны синтетически, это не фактический результат распознавания корпоративной модели.

## Пары для ответа

Inputs содержат references, query, product, kind подтверждённого контекста, approved, state и явные признаки этапа обработки. kind контекста не является gold типа нового query. В references есть ссылки на синтетические источники и признак source_verified. Query включает собственный product и consent. seen_message_ids моделирует ранее поставленные в очередь сообщения. Поле event отличает новое обращение от кандидата в рассылку после фикса.

**same_topic и eligibility — разные labels.** same_topic означает совпадение основной явно описанной проблемы с подтверждённым контекстом при том же product/kind/direction; при нехватке контекста значение null. Дополнительная индивидуально опасная просьба не отменяет сам факт упоминания известной проблемы. eligibility — допустимость обычного шаблона по безопасности, согласию, доказательствам, одобрению и текущему состоянию **до** смысловой проверки. Поэтому возможны и same_topic=true/eligibility=false, и same_topic=false/eligibility=true.

safe_action обозначает допустимую **подготовку**, а не внешнюю отправку:

| safe_action | Значение |
|---|---|
| queue_standard | Обычный фиксированный шаблон в очередь: совпала тема, известен продукт/тип/направление, источники проверены, согласие есть, человек одобрил, состояние open |
| operator | Отказ от автоматического шаблона: несовпадение/неясность, отсутствие доказательств/согласия либо индивидуальный денежный/учётный/инъекционный риск |
| needs_approval | Безопасная совпавшая тема ещё не одобрена человеком |
| needs_fix_approval | Кандидат в сообщение о фиксе ещё не прошёл нужные подтверждения |
| queue_fixed_notice | Отдельное уведомление об исправлении после проверки фикса, закрытия человеком и отдельного одобрения рассылки; обычный шаблон при этом недопустим |
| ignore_duplicate | Этот message_id уже ставился в очередь; повторная подготовка не выполняется |

Приоритет: индивидуальная безопасность/неопределённость и доказательства → смысловые guards → подтверждения состояния → постановка в очередь. Никакая близость текстов не разрешает обычный шаблон для денег, учётных данных, инъекции, отсутствия согласия или этапа после фикса. Подготовка fixed_notice — отдельный путь на старых обращениях, а не подтверждение того, что новая жалоба после фикса уже решена.

## Рабочий payload и метрики

Не передавайте всю строку tune в matcher или корпоративный gateway. Формируйте payload по белому списку полей inputs; gold/expected/topic_id/safe_action и диагностические причины остаются только в harness. Контрольные inputs уже не содержат этих полей, включая вложенные объекты; это проверяет validate.py.

Показывайте исходные знаменатели: все обращения/пары, уникальные сообщения, определённые/неопределённые темы, допустимые случаи, все ожидаемые queue_standard и отдельно queue_fixed_notice. Precision без recall/coverage и число отказов без пропусков положительных случаев недостаточны. Всеотказный алгоритм не считается хорошим по одной доле безопасных отказов. Сравнения используют одинаковые входы и определения TP/FN; исторические метрики всплесков не переносятся на эти две новые задачи.

## Проверка целостности

```bash
python3 -B evaluation/v5/validate.py
```

Команда проверяет схему, ID, product/kind в topic_id, разделение смысловых семейств и текстов между split, повторы авторов/доставок, независимость same_topic/eligibility, разрешения на стандартные и fixed-ответы, отсутствие gold в inputs и совпадение с lock. Она не загружает matcher или модели и не печатает контрольные ответы.
