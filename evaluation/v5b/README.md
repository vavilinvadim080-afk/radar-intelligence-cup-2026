# Независимый контроль v5b

Контроль сформирован отдельно от разработчика matcher, до исполнения нового backend на нём. Это синтетический набор одного независимого контекста, без реальных данных ГПН, экспертной корпоративной разметки или результатов модели.

## Передаваемый контракт

| Файл | Строки |
|---|---:|
| control-inputs.jsonl |120|
| control-gold.jsonl |120|
| reply-control-inputs.jsonl |80|
| reply-control-gold.jsonl |80|

Потребности:24 семейства×4 уникальных обращения,20 unknown,4 повторные доставки;116 уникальных id. В каждой семье повтор автора не даёт дополнительного голоса. Автоответ:6 новых семейств,20 допустимых стандартных подготовок и60 остальных случаев. Отдельные fixed-notice подготовки не увеличивают знаменатель стандартных позитивов. Истинность темы и eligibility — разные метки.

Gold хранится отдельно и не содержит predictions/scores. Формат — id + gold-блок разрешённого v5 tune; поля и выравнивание описаны в SCHEMA.json. Для повторных доставок порядок gold соответствует порядку inputs: один id встречается дважды с разным received_at и delivery-specific флагом. Группировать золотые строки только по id с потерей порядка нельзя.

## До freeze

Родитель/настройщик не читает gold, private/ или конкретные ответы. Ему передаются только пути, количества и SHA. Для настройки разрешён прежний v5 tune. Новые inputs не являются дополнительным tune; изменение порогов по их результатам запрещено.

Новый matcher, NLI/E5/Qwen-код и результаты моделей при подготовке не читались. Для непересечения читались только4 прежних файла inputs/tune, перечисленные с SHA в VALIDATION.json/CONTROL-LOCK.json. Старые отдельные gold не открывались. Отсутствие точных совпадений проверено кодом; новые предметные границы/намерения проверены вручную, без semantic scoring.

## Воспроизведение проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s evaluation/v5b -p test_validate.py
PYTHONDONTWRITEBYTECODE=1 python3 evaluation/v5b/validate.py --verify-lock
```

Обе команды используют только стандартную библиотеку, не импортируют backend и не исполняют модели. Первая проверяет валидатор на искусственных служебных fixtures, не на ответах модели; вторая сверяет SHA, не печатая gold. Полный `validate.py` проверяет структуру самого корпуса и читает gold: до freeze его запускает только независимый автор, после freeze — допускается при окончательном scoring. `--lock` создаёт контрольный lock лишь после успешной проверки. Существующий lock нельзя заменять для исправления неудобного результата.

Восемь unit-проверок: первоначальный RED6 failures на заглушке →GREEN8. Структурный аудит проверяет счёт, поля, выравнивание gold, раздельность меток, повторную доставку, необходимые условия стандартного ответа и отдельного fixed-notice, точные повторы старых текстов и topic_id tune. Это не машинная оценка истинности разметки и не обещание качества backend.

private/ содержит закрытые материалы авторинга и независимого семантического разбора. Перегенерация при существующем CONTROL-LOCK.json запрещена. При необходимости нового контроля создаётся новая версия, а не исправляется этот набор после просмотра score.
