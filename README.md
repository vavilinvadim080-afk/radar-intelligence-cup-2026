# Радар

Прототип для кейса компании «Газпром нефть»: собирает повторяющиеся обращения поддержки в темы для продуктовых команд и показывает работу с инцидентами. В карточке видны основания, цитаты и решение человека. Все демонстрационные обращения синтетические.

**Условия использования:** [Radar Evaluation License 1.0](LICENSE). Жюри разрешены скачивание и проверка решения; другое использование оригинальных материалов требует отдельного письменного разрешения. [Сторонние компоненты](THIRD_PARTY_NOTICES.md) сохраняют свои лицензии.

**Для жюри:** [скачать весь комплект ZIP](https://github.com/vavilinvadim080-afk/radar-intelligence-cup-2026/archive/refs/heads/main.zip). Распакуйте архив, сначала откройте `video/index.html` (ролик 3:39), затем `presentation/radar.html` (13 слайдов). Установка Python для просмотра не нужна. HTML-файлы открываются после скачивания; GitHub показывает их исходный код.

Материалы удобно смотреть в таком порядке: ролик, презентация, затем приложение и исходники. Репозиторий содержит самостоятельную копию приложения со своими зависимостями и точкой запуска.

Откройте [плеер](video/index.html) или скачайте [radar.mp4](video/radar.mp4). Продолжительность 3:39, разрешение 1080p, 30 кадров в секунду.

Актуальные показатели качества, экономика и ограничения приведены в презентации и [QUALITY.md](docs/QUALITY.md). Числа из разных этапов проверки нельзя объединять в один результат.

## 3. Демо и полный исходный код

В приложении два пути. «Потребности» собирают устойчиво повторяющиеся пожелания, ошибки и неудобства, даже когда всплеска нет. «Инциденты» показывают обнаружение всплеска, связь с релизом, решение оператора и проверку исправления.

Локальный запуск использует шаблоны и правила. Корпоративный шлюз представлен адаптером: для подключения нужны согласованные адреса, доступы и параметры внутренней платформы. Доступа к реальным тикетам и внутренним моделям компании при подготовке не было.

### Запуск

Нужен Python 3.12. Откройте терминал в корне репозитория. На macOS и Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

На Windows в PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
```

В Windows cmd окружение активируется командой `.venv\Scripts\activate.bat`; установка зависимостей и запуск такие же.

`venv` создаёт отдельное окружение в `.venv`, активация выбирает его Python для текущего терминала. `python -m pip` устанавливает пакеты в это окружение, `-r requirements.txt` берёт список зависимостей из файла. `run.py` запускает приложение.

Сервер работает локально на порту **8799**. Браузер открывается автоматически; токен передаётся во фрагменте адреса после `#`. Для запуска без открытия браузера:

```sh
python run.py --no-open
```

Токен авторизации создаётся локально при первом старте. [.env.example](.env.example) содержит пример настроек. Публиковать рабочие токены, ключи и заполненные файлы с секретами не следует; общего заранее заданного токена для всех копий нет. Для просмотра ролика и презентации установка Python не требуется.

Окно входа просит **локальный ключ Радара**, который разрешает просмотр и кнопки решений. Это не ключ внешней или корпоративной модели: покупать либо получать внешний API-ключ для демо не нужно. Если вкладка открыта вручную и ключа в ней нет, в том же каталоге и окружении получите ссылку:

```sh
python run.py --access-url
```

Команда только показывает приватную ссылку, сервер повторно не запускается. Откройте её на своём компьютере; ссылку и ключ не отправляйте в переписку и не добавляйте в Git. При своём порте укажите его, например `--port 8799`. Рабочий ключ и секрет псевдонимизации хранятся в создаваемом локально `mvp-v13-adapted/runtime/.secrets.json`; этот каталог исключён из Git и отправляемого архива. В репозитории есть имена переменных, пустые настройки и явно тестовые ключи для проверок, но нет рабочих ключей сервиса или внешних API.

### Что попробовать

При первом открытии «Инцидентов» подготовка синтетического сценария может занять **30-90 секунд**. Дождитесь появления данных. Во вкладке «Потребности» нажмите **«Загрузить пример»**: появятся 32 обращения. Повторная загрузка не увеличивает счётчики. Дата примера зафиксирована для воспроизводимости окна наблюдения.

В «Потребностях» откройте тему, сопоставьте цитаты и число разных авторов, посмотрите доступные решения команды. Стартовое правило накопления темы: три разных автора за 28 дней. Это настройка демонстрации и будущего пилота. Разделение учитывает продукт, тип, цель и направление изменения; ошибочные объединения и пропуски всё равно возможны.

В «Инцидентах» пройдите от решения «Наш баг» к проверке фикса и подтверждению закрытия. Шаблонный автоответ включается оператором. Кнопки подготовки ответов и рассылки создают записи в локальной очереди, наружу ничего не отправляется. Выпуск исправления и задачи трекера здесь тоже имитируются. Экспериментальный смысловой автоответ v5c проверяется отдельно; в контроле есть ошибочные допуски.

### Где лежит код

В комплект входит полный исходный код приложения, включая оба режима, тесты и скрипты:

| Путь | Содержимое |
|---|---|
| [radar_app/](radar_app/) | Ядро потребностей, шлюз, маскирование, инструменты и расчёты |
| [mvp-v13-adapted/](mvp-v13-adapted/) | Приложение, интерфейс, детектор инцидентов и проверка фикса |
| [tests/](tests/) и [тесты приложения](mvp-v13-adapted/tests/) | Проверки поведения ядра и приложения |
| [scripts/](scripts/) | Скрипты оценки, расчётов и подготовки материалов |
| [data/](data/) | Синтетические примеры, параметры и сохранённые результаты |
| [evaluation/v5c/](evaluation/v5c/) и [v5b](evaluation/v5b/) | Синтетические наборы и протоколы независимых проверок |

Веса моделей, локальные секреты, рабочие базы, личные учебные материалы и прежние версии в комплект не входят. Обычное демо не требует скачивания нейросетевых весов. Для изучения устройства начните с [архитектуры](docs/ARCHITECTURE.md), затем откройте [интеграции](docs/INTEGRATIONS.md) и [ограничения](docs/LIMITATIONS.md).

Команда функциональных проверок из корня с активированным окружением:

```sh
python -m pytest -q tests mvp-v13-adapted/tests
```

`pytest` запускает проверки из двух каталогов, `-q` сокращает вывод. Успешные функциональные тесты сами по себе не подтверждают качество группировки или готовность корпоративных интеграций.

## Проверки качества и роли моделей

В [отдельном офлайн-тесте автоответа](docs/REPLY-EXPERIMENT-V7B.md) Qwen3 Reranker 4B получил Precision/Recall **83,3%/83,3%**: TP5/FP1/FN1 на 24 сценариях, 6 допустимых. На том же наборе и с той же политикой у 0.6B четыре ложных допуска, у 4B один. Это сравнение проверяющих моделей в одной задаче; результат не переносится на группировку или внутренние обращения заказчика. Уведомления о фиксе проверены отдельно: четыре сценария, два допустимых, Precision100%/Recall50%.

Для потребностей сохранён другой контроль: 184 уникальных обращения, Accuracy типа **83,2%**, Precision/Recall группировки **50,8%/55,0%**. Это попарная оценка объединений; полезность продуктовых карточек требует отдельной проверки. Новых замеров группировки на 4B нет.

Embeddings находят смысловых кандидатов. Reranker проверяет пары, NLI добавляет признаки совместимости и риска. Права, инструменты, лимиты, очередь и журнал выполняются кодом. По умолчанию приложение использует правила и шаблоны; семантический v5c запускается отдельно с явным разрешением эксперимента. Новый 4B участвует только в офлайн-проверке автоответа и не подключён к основному запуску. Адаптер к внутренним моделям компании требует отдельного подключения и приёмки.

Автоматическая отправка отключена: у кандидата остаётся ложный допуск, внешняя доставка не подключена. Все оценки получены на синтетике. Полные результаты вариантов, история статистического детектора и протоколы сохранены в [QUALITY.md](docs/QUALITY.md) и каталогах `evaluation/`, `reports/`.

Независимо пересчитать сохранённые предсказания без нейромоделей:

```sh
python3 -B scripts/check_saved_metrics_v5c.py
python3 -B scripts/check_saved_reply_v7b.py
```

Команды проверяют хэши опубликованных входов, исходников, предсказаний и арифметику. Они не запускают модели повторно; отсутствующие веса перечисляются явно.

## Документы решения и эффект

[solution.pdf](submission/solution.pdf) и [solution.md](submission/solution.md) содержат официальные пункты 1-4 и 6 в пределах 15 000 символов. Пункт 5 вынесен в [effect.md](submission/effect.md); [effect.pdf](submission/effect.pdf) служит вспомогательной копией. [description.txt](submission/description.txt) подготовлен для поля «Описание решения».

По условию кейса «Газпром нефть» в поддержке около 40 сотрудников, модели и инфраструктура бесплатны. Базовый расчёт даёт 2880 часов ёмкости в год: `40 × 48 недель × (2 − 0,5 часа)`. Экономия 1,5 часа задана в неделю на одного сотрудника. При остальных одинаковых вводных сценарии 3 и 6 ч/нед дают 5760 и 11520 ч/год. **Дисконтированный денежный эффект за 3 года**: **973 333,33 / 1 946 666,67 / 3 893 333,33 ₽** соответственно для 1,5 / 3 / 6 ч/нед. Это приведённая стоимость предполагаемого реализуемого денежного эффекта до вычета затрат на внедрение и эксплуатацию. Общие допущения: цена часа 800 ₽, денежная реализация 25% стоимости времени, освоение 50%/100%/100% по годам, дисконт 20%. Часы и исходные трудозатраты не измерены; измеренного минимума пока нет. Подробный расчёт и отдельный вывод о пределе вложений при нулевых дополнительных затратах находятся в [пункте 5](submission/effect.md), данные в [economics-weekly.json](data/economics-weekly.json). Потенциал автоответа в базовый эффект не добавлен.

Следующий этап предполагает пилот с разрешённой обезличенной историей: согласовать разметку, измерить качество тем и время поддержки и продуктовых команд, проверить внутренние интеграции. Решение о внедрении принимается по результатам такого пилота.
